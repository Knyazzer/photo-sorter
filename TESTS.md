# Photo Sorter 2.0 — smoke / integration checks

Проверки выполнены на отдельном тестовом корне с двумя залами и реальными JPEG-файлами.

## Статическая проверка

```bash
npm run check
```

Проверены синтаксис:

- `server.js`;
- `lib/files.js`;
- `lib/photo-name.js`;
- `lib/photo-metadata.js`;
- `lib/photo-store.js`;
- `lib/photo-service.js`;
- `public/app.js`.

## API / filesystem

Проверено:

1. Индексация двух залов и создание `raw / Люди / Оборудование`.
2. `RAW → Люди`.
3. Создание ФИО через API и автоматическое создание папки.
4. `Люди → ФИО` с автоматическим именем `ФИО_ДЕНЬ_НОМЕР.ext`.
5. `ФИО → Оборудование` с техническим стабильным именем оборудования.
6. Undo возвращает фотографию из оборудования к прежнему ФИО.
7. `ФИО → RAW` восстанавливает исходное `photo_...` имя.
8. Batch-классификация фотографий из разных залов не смешивает залы.
9. Удаление пустого ФИО.
10. Удаление ФИО с фотографиями требует подтверждения и возвращает фото в RAW.
11. Переименование ФИО физически переносит/переименовывает принадлежащие ему фото.
12. После перезапуска сервера `photo_id` остаются прежними.
13. Ручное перемещение фото через файловую систему + `Синхронизировать` сохраняет прежний `photo_id` по файловому отпечатку.
14. Попытка перейти через `../` в файловом браузере блокируется.
15. Если целевой файл уже существует, операция классификации блокируется, а исходный файл остаётся на месте.
16. Endpoint метаданных возвращает размер, формат, разрешение и доступные EXIF-поля.

## Примечание по browser UI

Frontend прошёл синтаксическую проверку и проверен через соответствующие API-сценарии. Автоматический headless Chromium в контейнере оказался нестабилен, поэтому полноценный e2e-клик-тест DOM в этот прогон не включён.
