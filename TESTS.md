# Проверенные сценарии

## 2.6

1. Production требует `PHOTO_SORTER_PASSWORD` ровно из 5 цифр.
2. Вход требует одновременно имя и правильный 5-значный PIN.
3. Имя записывается в подписанную auth-cookie и отображается в `/api/sessions`.
4. Технический код сессии больше не показывается пользователю вместо имени.
5. Ручная кнопка и API `/api/sync` удалены; upload finish автоматически выполняет sync.
6. Файловый браузер отдаёт `photoCount` для каждой папки, включая фото во вложенных подпапках.
7. `npm run check` проходит для backend/frontend JS.

## 2.3

1. Вход больше не требует логин — отправляется только общий пароль.
2. Неверный общий пароль → HTTP 401.
3. Правильный локальный пароль `photo-sorter` → HTTP 200 и подписанная session cookie.
4. При локальном HTTP cookie не получает атрибут `Secure`, поэтому браузер отправляет её на следующие API-запросы.
5. После входа `/api/auth/status` возвращает `authenticated:true`.
6. Защищённый `/api/system` доступен с полученной cookie.
7. `npm run check` проходит для backend/frontend JS.
8. Отдельный upload password сохраняется независимо от общего пароля.

## 2.2

Проверено на отдельном временном проекте и отдельной SQLite БД:

1. `/health` отвечает без авторизации.
2. `/api/auth/status` до входа возвращает `authenticated:false`.
3. неверный общий пароль → HTTP 401.
4. правильный общий логин/пароль → подписанная cookie и доступ к API.
5. неверный upload password → HTTP 403.
6. правильный upload password → доступ к upload API.
7. resumable upload одного файла двумя chunk'ами.
8. сервер сообщает фактический offset уже принятой части.
9. импорт старого пути `Арма/photo_1...jpg` физически создаёт `Арма/raw/photo_1...jpg`.
10. после upload finish выполняется индексация и фото появляется в mode1.
11. `RAW → Люди`.
12. `Люди → ФИО` с автоматическим переименованием.
13. удаление ФИО с фото требует подтверждения.
14. после подтверждения фото возвращается в `Арма/Люди/`, а не в `raw`.
15. статус фотографии после удаления ФИО — `people`, `person_id=null`.
16. исходное имя восстанавливается при возврате из ФИО в корень `Люди`.
17. `npm run check` проходит для server/lib/frontend JS.

## Ограничение текущей среды проверки

Docker daemon в рабочей среде сборки недоступен, поэтому `docker compose up --build` здесь не запускался. Dockerfile/Compose подготовлены для Node 22 Debian image; фактическую сборку контейнера нужно выполнить на VDS командой из `DEPLOYMENT.md`.

## Smart chips режима «Люди / оборудование»

- По умолчанию активны все три фильтра: `Люди`, `Оборудование`, `RAW`.
- Отключение чипа скрывает соответствующие карточки без повторного создания DOM-сетки и без повторного запроса thumbnails.
- Статусы `people` и `person` относятся к чипу `Люди`.
- При активном только `RAW` классификация фото в `Люди`/`Оборудование` сразу скрывает карточку.
- При активном только `Люди` обратная классификация в `RAW`/`Оборудование` сразу скрывает карточку.
- Если выключены все три чипа, отображается штатное пустое состояние.
- Shift-выделение охватывает только видимые фотографии.


## 2.6 — вход, сессии, папки

- В production приложение не запускается, если `PHOTO_SORTER_PASSWORD` не равен пяти цифрам.
- Вход без имени отклоняется; PIN не из 5 цифр отклоняется.
- После входа `/api/sessions` показывает введённое имя вместо `Сессия ABC123`.
- В файловом браузере каждая папка содержит `photoCount`, включая фотографии во вложенных папках.
- В верхней панели отсутствует ручная кнопка «Синхронизировать».
