# Photo Sorter 2.8

- Удалены ручные кнопки «Обновить» из всех трёх режимов.
- Добавлена кнопка «Инструкция» справа от «Люди / ФИО».
- Инструкция открывается в модальном окне поверх рабочего интерфейса.
- Автоматическое обновление данных и realtime-сессии сохранены.

# 2.7.0

- Smart-чипы `Люди / Оборудование / RAW` ускорены: фильтрация больше не делает O(n²)-поиск и не перебирает тысячи DOM-карточек.
- Для mode1 фильтр переключается классом контейнера; счётчики залов считаются по данным, а не через DOM.
- Оптимизировано выделение карточек: обновляются только реально изменённые элементы.
- Активные пользователи теперь обновляются realtime через SSE; вход/режим/зал появляются без перезагрузки, закрытая вкладка исчезает автоматически.
- Глобальная кнопка и API Undo удалены.
- Загрузка фотографий убрана из основного интерфейса и вынесена на `/upload`.
- `/upload` сначала запрашивает отдельный upload-пароль, затем открывает выбор папки и показывает постоянный прогресс загрузки.
- Upload API защищён отдельным паролем и больше не требует обычной пользовательской сессии.

# 2.6.0

- Удалена ручная кнопка и API `/api/sync`: синхронизация выполняется при старте, настройке корня и после загрузки.
- Вход теперь требует имя пользователя и общий 5-значный цифровой PIN.
- PIN вводится в пяти отдельных цифровых полях; поддержаны автопереход, Backspace и вставка всех 5 цифр.
- Имя пользователя подписывается в auth-cookie и отображается в активных сессиях вместо технического кода.
- У папок файлового браузера отображается количество фотографий во всей папке с учётом вложенных подпапок.

# Changelog

## 2.5.0

- Добавлены smart chips в режиме «Люди / оборудование»: `Люди`, `Оборудование`, `RAW`.
- Каждый тип можно независимо показывать/скрывать без перезагрузки сетки и повторной загрузки thumbnails.
- Фото со статусом `person` относится к фильтру «Люди».
- После классификации карточка сразу учитывает активный фильтр: например, при режиме только RAW отсортированное фото исчезает из текущего представления.
- В чипах отображаются количества фотографий по категориям, заголовки залов показывают число видимых фото.
- Shift-выделение в режиме фильтра работает только по видимым карточкам.

# 2.4.0

- Для сеток добавлен отдельный лёгкий endpoint `/api/thumb` (WebP до 360×270) вместо использования preview 560×420.
- Preview-панель использует отдельный WebP до 1280×960; оригинал загружается только в полноэкранном просмотре.
- Thumbnail URL по `photo_id + contentRevision` теперь получает `Cache-Control: private, max-age=31536000, immutable`, поэтому переход между папками не перекачивает те же изображения.
- После старта, ручной синхронизации и завершения загрузки запускается фоновый прогрев grid-thumbnail cache с ограниченной конкуренцией.
- Сохранён фикс Unicode HTTP headers из 2.3.2.

# 2.3.2

- Исправлены все browser fetch-ошибки `String contains non ISO-8859-1 code point`: кириллица больше не передаётся в custom HTTP headers без кодирования.
- Локальный `start-windows.bat` теперь проверяет, что `sharp` действительно загружается через Node.js; при сломанной/неполной установке выполняется восстановление зависимостей.
- Thumbnail fallback больше не засоряет консоль отдельным предупреждением для каждой фотографии.

# 2.3.1

- Исправлена ошибка браузера `String contains non ISO-8859-1 code point`: кириллические названия залов больше не передаются в HTTP headers в сыром виде.
- Служебные header-values (`x-client-hall`, `x-client-mode`, `x-upload-password`) кодируются на frontend и безопасно декодируются на backend.
- Это исправляет Preview/синхронизацию для залов с кириллическими названиями и позволяет использовать не-ASCII пароль загрузки.

- контейнер рассчитан на подключение напрямую к Docker-сети Nginx Proxy Manager без публичного порта;
- добавлен `/health` для Docker healthcheck;
- runtime пути БД и cache теперь задаются environment variables;
- удалён старый access-token механизм;
- подготовлен deployment для `photo-sorter.knzteam.ru`.
