# Photo Sorter 2.2

Photo Sorter — веб-приложение для просмотра и сортировки фотографий по залам, категориям «Люди / Оборудование» и конкретным ФИО.

## Текущая архитектура

```text
Файловый браузер
      │
      ├── Люди / Оборудование
      └── Люди / ФИО

Файловая система + стабильный photo_id + SQLite
```

Для каждого зала:

```text
Зал/
├── raw/
├── Люди/
│   ├── Иванов Иван/
│   └── ...
└── Оборудование/
```

`raw` — только первично неотсортированные фотографии. Если удалить ФИО человека, его фотографии возвращаются в **корень `Зал/Люди`**, потому что уже известно, что это люди.

## Что есть в 2.2

- файловый браузер с breadcrumb;
- постоянный Preview + EXIF/metadata;
- полноэкранный просмотр;
- стабильный `photo_id` независимо от текущего имени и пути;
- SQLite + WAL;
- безопасные файловые move/rename без молчаливой перезаписи;
- `raw ↔ Люди ↔ Оборудование`;
- назначение и переназначение ФИО drag-and-drop;
- множественный выбор;
- Undo по отдельной browser-сессии;
- optimistic version control — устаревшая параллельная операция получает `409 Conflict`;
- активные сессии и polling изменений без полной перезагрузки фотосетки;
- WebP thumbnail-cache по `photo_id`;
- общий login/password для команды;
- отдельный upload/admin password;
- resumable folder upload по chunk'ам;
- Docker deployment;
- работа за Nginx Proxy Manager на поддомене.

## Авторизация

В production значения задаются только через environment variables:

```text
PHOTO_SORTER_USERNAME
PHOTO_SORTER_PASSWORD
PHOTO_SORTER_UPLOAD_PASSWORD
PHOTO_SORTER_SESSION_SECRET
```

Пользовательский пароль даёт доступ к просмотру и сортировке.

`PHOTO_SORTER_UPLOAD_PASSWORD` дополнительно требуется для:

- загрузки папки фотографий;
- ручного изменения корня проекта в локальной конфигурации.

В Docker/VDS корень фиксирован как `/storage/photo-sorter`.

Пароль загрузки не сохраняется в `localStorage` и используется только в памяти текущей страницы.

## Многосессионная работа

Все сотрудники могут входить под одним общим аккаунтом. При этом каждый браузер получает собственный `session_id`.

Операции над фотографиями используют поле `version`. Пример:

```text
браузер A получил photo version=12
браузер B получил photo version=12

A → Люди
version становится 13

B пытается → Оборудование с expected version=12
→ 409 Conflict
→ интерфейс получает актуальное состояние
```

То есть один общий логин не означает одну общую рабочую сессию.

## Производительность изображений

Сетка использует URL вида:

```text
/api/preview?id=<photo_id>
```

Он не меняется при физическом переносе или переименовании файла.

Для сетки создаётся WebP thumbnail, оригинал нужен только для большого просмотра. После сортировки затронутые карточки обновляются точечно — вся сетка не удаляется и не загружается заново.

## Загрузка 1.19 ГБ фотографий

Через кнопку **«Загрузить фото»** выбирается корневая папка проекта. Каждый файл отправляется отдельными chunk'ами до 8 MiB. При разрыве соединения сервер знает уже записанный offset и может продолжить файл.

После завершения запускается индексация SQLite.

Фотографии хранятся на диске VDS, а не в GitHub.

## Локальный запуск для разработки

Требуется Node.js 22.5+.

```bash
npm install
npm start
```

Если `NODE_ENV` не равен `production` и переменные авторизации не заданы, используются только локальные dev-значения:

```text
login: photo
password: photo-sorter
upload password: upload-photo-sorter
```

Для production такие defaults запрещены — приложение не стартует без явно заданных секретов.

## Docker / VDS

Полная последовательность для `photo-sorter.knzteam.ru` находится в [`DEPLOYMENT.md`](DEPLOYMENT.md).

Коротко:

```bash
cp .env.example .env
# заполнить пароли, SESSION_SECRET и NPM_NETWORK
mkdir -p storage runtime/data runtime/cache
docker compose up -d --build
```

После этого в Nginx Proxy Manager:

```text
photo-sorter.knzteam.ru → http://photo-sorter:3000
```
