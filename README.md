# Photo Sorter Local 2.0

Локальное веб-приложение для просмотра и сортировки фотографий по залам, категориям и ФИО.

## Требования

- **Node.js 22.5+** — используется встроенный `node:sqlite`.
- Windows, macOS или Linux.
- Фотографии находятся в одном постоянном корне проекта.

Внешние npm-пакеты не требуются.

## Запуск

На Windows:

```text
start-windows.bat
```

Или вручную:

```bash
node server.js
```

По умолчанию сервер запускается на порту `3000`.

Первый запуск открывает одноразовую настройку корня проекта, если он ещё не задан. После этого путь сохраняется в `data/config.json` и приложение всегда открывается сразу в файловом браузере.

Корень можно задать без интерфейса:

```powershell
$env:PHOTO_SORTER_ROOT="D:\ФОТО РОЗ"
node server.js
```

## Структура файлов

Для каждого зала приложение использует:

```text
Зал/
├── raw/
├── Люди/
│   ├── Иванов Иван Иванович/
│   └── ...
└── Оборудование/
```

- `raw` — неотсортированные фотографии;
- `Люди` — фотографии, классифицированные как люди;
- `Люди/ФИО` — фотографии, назначенные конкретному человеку;
- `Оборудование` — фотографии оборудования.

Фотографии **никогда не переносятся между залами**.

## Главный экран — файловый браузер

После запуска приложение открывается во вкладке **«Файлы»**.

- навигация выполняется через breadcrumb `Проект / Зал / Люди / ФИО`;
- отдельные кнопки «Корень», «Выше», «Назад», «Сменить папку» отсутствуют;
- справа всегда находится Preview;
- клик по фото показывает Preview и доступные метаданные;
- клик по большой фотографии в Preview открывает полноэкранный просмотр;
- `Esc` закрывает полноэкранный просмотр.

Preview показывает доступные данные файла и EXIF: размер, разрешение, дату съёмки, камеру, объектив, ISO, выдержку, диафрагму, фокусное расстояние, GPS и другие поддержанные поля.

## Режим «Люди / оборудование»

В режиме отображается единая лента фотографий, разделённая по залам.

Можно выделять несколько фотографий:

- обычный клик — выбрать одну;
- `Ctrl/Cmd + клик` — добавить/убрать из выделения;
- `Shift + клик` — выбрать диапазон.

Действия:

- `1` → Люди;
- `2` → Оборудование;
- `0` → вернуть в RAW.

Можно повторно классифицировать уже отсортированное фото, в том числе:

```text
ФИО → Оборудование
Оборудование → Люди
Люди → RAW
Оборудование → RAW
```

При возврате в RAW используется сохранённое `original_filename`.

## Режим «Люди / ФИО»

Сначала выбирается конкретный зал. Другие залы в этот режим не подмешиваются.

Слева находится список ФИО, справа — единая сетка фотографий из `Зал/Люди`, включая уже назначенные папки ФИО.

### Добавление ФИО

Введите имя в поле и нажмите `Enter`.

Папка создаётся автоматически:

```text
Зал/Люди/ФИО/
```

Отдельной кнопки «Сохранить список» нет.

### Назначение фотографии

Зажмите непосредственно карточку фотографии и перетащите её на ФИО.

Если выделено несколько фотографий, переносятся все выбранные.

Имя автоматически меняется на:

```text
ФИО_ДЕНЬ_НОМЕРФОТО.ext
```

### Переназначение

Фото уже назначенного человека можно перетащить на другого человека. Файл физически переместится и автоматически переименуется.

### Отмена сортировки фотографии

Правой кнопкой по фотографии → **«Отменить сортировку → RAW»**.

Исходное имя восстанавливается из БД.

### Удаление ФИО

Если у ФИО нет фотографий — запись и пустая папка удаляются.

Если фотографии есть — приложение запрашивает подтверждение. После подтверждения фотографии сначала возвращаются в RAW с исходными именами, и только затем удаляется запись ФИО и пустая папка.

## SQLite и `photo_id`

Рабочее состояние хранится в:

```text
data/photo-sorter.sqlite
```

У каждой фотографии есть стабильный UUID `photo_id`.

Хранятся, в частности:

- зал;
- `original_filename`;
- текущее имя;
- текущий путь;
- статус;
- категория;
- ФИО;
- время съёмки;
- номер фото;
- файловый отпечаток;
- история операций.

Старый `data/state.json` больше не является рабочей БД. В комплекте также сохранена копия `data/state.legacy.json`.

## Синхронизация файловой системы

Кнопка **«Синхронизировать»** повторно сканирует проект и сопоставляет БД с диском.

Система обнаруживает:

- новые фотографии;
- исчезнувшие файлы;
- ручное перемещение/переименование;
- изменение текущего состояния фотографии.

Для ручного перемещения используется файловый отпечаток, поэтому при однозначном совпадении сохраняется прежний `photo_id`.

## Undo

`Ctrl/Cmd + Z` или кнопка **«Отменить»** отменяет последнюю группу файловых операций.

Undo не перезаписывает существующие файлы. Если исходный путь уже занят, операция останавливается с ошибкой.

После удаления или переименования ФИО текущая цепочка Undo инвалидируется, чтобы старые пути не могли привести к некорректному восстановлению.

## Имена оборудования

Пока окончательная бизнес-схема имени оборудования не утверждена, используется техническое стабильное имя:

```text
EQ_<8 символов photo_id>_ДЕНЬ_НОМЕР.ext
```

Например:

```text
EQ_d36dda12_11_123.jpg
```

Это локальная naming strategy; её можно заменить позже, не меняя `photo_id` и модель БД.

## `_thumb`

Файлы с `_thumb` не считаются фотографиями модели и не индексируются как отдельные объекты.

Приложение **не удаляет их автоматически**.

## Важное ограничение при миграции старых данных

Если фотография уже была переименована в старой версии и на момент первого запуска 2.0 находится внутри `Люди/ФИО`, точное исходное имя `photo_...@...` невозможно восстановить только из имени вида `ФИО_ДЕНЬ_НОМЕР`.

Для таких уже существующих legacy-файлов приложение не придумывает дату/время. После того как фотография зарегистрирована в новой БД, дальнейшие перемещения и переименования сохраняют её идентичность и историю.
