# Аудит Photo Sorter — реализованные изменения

## Критические / High

### `state.json` как источник истины

**Было:** выбранный root, списки ФИО, skip и глобальный undo хранились в одном JSON-файле. JSON мог расходиться с файловой системой после ручных операций.

**Исправлено:** рабочая модель перенесена в SQLite. `state.json` сохранён только как legacy-источник для возможной первичной миграции пути.

### Идентификация фотографии по имени и пути

**Было:** логика зависела от текущего имени файла и его папки.

**Исправлено:** введён стабильный UUID `photo_id`, `original_filename`, текущее имя/путь, статус, ФИО и файловый отпечаток.

### Неверный источник режима 1

**Было:** очередь режима 1 читала изображения непосредственно из корня зала.

**Исправлено:** входное состояние — `Зал/raw`. При этом режим 1 показывает и уже отсортированные фото, чтобы поддерживать повторную классификацию.

### Режим ФИО видел только непосредственные файлы `Люди`

**Было:** фотографии внутри `Люди/ФИО` не участвовали в режиме 2.

**Исправлено:** режим ФИО собирает единое состояние `Люди` + все папки конкретных людей выбранного зала.

### Path traversal / произвольные абсолютные пути

**Было:** часть API позволяла работать с произвольными абсолютными папками локальной машины.

**Исправлено:** пользовательский браузер работает только относительными путями внутри фиксированного root. Добавлена проверка lexical + realpath containment; symlink-каталоги не используются для навигации.

### Небезопасное перемещение с возможным overwrite

**Было:** `access(target)` + `rename()` оставляли TOCTOU-окно; на Unix `rename` способен перезаписать target.

**Исправлено:** move использует hard-link + unlink с запретом существующего target; для несовместимых файловых систем — `copyFile(... COPYFILE_EXCL)` + unlink и rollback при ошибке.

## Medium

### Глобальный Undo

**Было:** одна стековая история в JSON.

**Исправлено:** операции записываются в SQLite группами `batch_id` и привязываются к отдельному `session_id` браузера. Undo одной рабочей сессии не отменяет действия другой.

### Ручные изменения через Explorer

**Было:** состояние легко расходилось с диском.

**Исправлено:** добавлен scan/sync; новые и отсутствующие файлы выявляются, а ручное перемещение при однозначном файловом отпечатке сохраняет прежний `photo_id`.

### EXIF / время съёмки

**Было:** состояние в основном выводилось из имени.

**Исправлено:** добавлен metadata-слой для JPEG/PNG/WebP; для JPEG читаются базовые EXIF-поля, включая дату, камеру, ISO, оптику и GPS при наличии. Приоритет времени: EXIF, затем исходное имя; файловое mtime показывается отдельно.

## UX

- файловый браузер стал главным экраном;
- breadcrumb заменил «Корень/Выше/Назад»;
- постоянный Preview справа;
- отдельная вкладка «Информация» удалена;
- режим 1 заменён на сетку с множественным выбором;
- режим ФИО работает внутри конкретного зала;
- drag начинается непосредственно с фотографии;
- список ФИО сохраняется автоматически;
- удаление ФИО с фотографиями возвращает их в корень `Зал/Люди`, сохраняя классификацию «Люди»;
- правый клик по фото в режиме ФИО позволяет вернуть его в RAW.

## Оставлено на следующие этапы

- индивидуальные аккаунты/роли при необходимости (сейчас используется обязательное имя + общий 5-значный PIN и отдельные browser-сессии);
- аватары и расширенные статусы присутствия при необходимости;
- PostgreSQL при необходимости (VDS/Docker уже подготовлены);
- полноценный учёт оборудования;
- серверная генерация уменьшенных thumbnails отдельным image pipeline.

Добавлен WebP thumbnail-cache по стабильному `photo_id` через Sharp. Оригинал загружается для большого просмотра, а сетка использует уменьшенные preview и точечные DOM-обновления.
